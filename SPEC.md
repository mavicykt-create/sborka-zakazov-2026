# SPEC — «Сборка заказов 2026»

## 1. Назначение

Сервис получает товарный чек XLSX (сначала вручную или через Gmail), превращает его в складской заказ, сортирует товары, распределяет позиции между активными сборщиками и сопровождает сборку голосом через Android-гарнитуру.

## 2. Источник заказа

Первая версия принимает XLSX такого типа, как `test-data/sample-order-12293.xlsx`.

Нужно извлекать:
- номер документа;
- дату документа;
- склад;
- номер строки;
- код/штрихкод;
- наименование товара;
- количество упаковок (первая колонка количества);
- количество штук (вторая колонка количества).

Цена и сумма могут сохраняться для диагностики импорта, но не показываются сборщику и не участвуют в сборке.

### Правило типа отбора

- Если `packageQuantity > 0`: `pickType = PACKAGE`, `pickQuantity = packageQuantity`.
- Если `packageQuantity` пусто/0, но `pieceQuantity > 0`: `pickType = PIECE`, `pickQuantity = pieceQuantity`, позиция отмечается `ШТУЧНЫЙ ТОВАР`.
- Если правило не смогло однозначно определить тип — `pickType = REVIEW`, заказ попадает в «Требует проверки».
- Администратор может вручную изменить тип отбора до начала сборки.

## 3. Группировка

`groupKey` = первое слово наименования после trim, в верхнем регистре, без ведущей пунктуации.

Примеры: `КОФЕ`, `ЖК`, `ЖИДКОНФ`, `ПЛИТКА`, `ШБ`.

Сначала сортируем группы по алфавиту, затем товары внутри группы по наименованию.

## 4. Защита от дублей

Одинаковый документ не должен создавать второй заказ. Для первой версии уникальность: `documentNumber + documentDate + warehouse`. Позже добавить Gmail message id / hash вложения.

## 5. Сборщики

У каждого сборщика:
- логин;
- пароль (хэш);
- имя;
- активность;
- статус смены: `OFF_SHIFT`, `AVAILABLE`, `BUSY`.

## 6. Распределение

Заказ делится между выбранными активными сборщиками максимально равномерно по количеству позиций. Разница между количеством позиций у сборщиков не более 1.

В первой версии одна товарная строка целиком назначается одному сборщику.

## 7. Android / голос

Основные команды:
- `Взял` — подтвердить текущую позицию;
- `Повтори` — повторить название и количество;
- `Сколько` — повторить только количество;
- `Не нашёл` — отметить отсутствие и перейти дальше;
- `Пропусти` — оставить незавершённой и перейти дальше;
- `Назад` — предыдущая позиция;
- `Отмени` — отменить последнее подтверждение;
- `Осталось` — сообщить остаток позиций;
- `Пауза` / `Продолжить`.

Для `PIECE` перед названием произносить: «Штучный товар».

## 8. Звуковые сигналы

Сигналы короткие, приятные и различимые без взгляда на экран:
- подтверждение `Взял` — короткий восходящий chime;
- переход к следующей позиции — отдельный мягкий tick/chime;
- `Повтори` — нейтральный короткий сигнал;
- `Не нашёл` — мягкий нисходящий сигнал;
- команда не распознана — два коротких сигнала;
- ошибка/невозможное действие — заметный, но не резкий сигнал;
- штучный товар — отдельный короткий pre-alert перед речью;
- завершение личной части — короткая мелодия;
- завершение всего заказа — отдельная мелодия.

Звук «принято» проигрывается только после надёжного сохранения действия локально. При отсутствии сети действие попадает в очередь синхронизации и UI явно показывает offline.

## 9. Главный терминал

Главная страница показывает:
- количество новых заказов;
- заказы в сборке;
- проблемные позиции;
- готовые заказы;
- карточки сборщиков (`AVAILABLE/BUSY/OFF_SHIFT`);
- прогресс текущих заказов;
- блок «Требует внимания» (`NOT_FOUND`, `SKIPPED`, ошибки импорта).

Разделы:
- Главная;
- Заказы;
- Сборщики;
- Проблемы;
- История;
- Настройки.

Для заказа доступны: распределить, перераспределить незавершённые позиции, открыть позиции, открыть сборщика, завершить/закрыть заказ.

## 10. Статусы

Заказ:
`NEW -> READY -> ASSIGNED -> PICKING -> REVIEW_REQUIRED? -> COMPLETED -> CLOSED`

Позиция:
`PENDING -> ASSIGNED -> ACTIVE -> PICKED | NOT_FOUND | SKIPPED`

## 11. Журнал действий

Не удалять историю команд. Сохранять события:
- назначение позиции;
- начало сборки;
- `PICKED`;
- отмена;
- `NOT_FOUND`;
- `SKIPPED`;
- передача другому сборщику;
- завершение.

У события: время сервера, время устройства, пользователь, позиция, тип события, metadata.

## 12. Лист сборки / PDF

После завершения формировать итоговый «Лист сборки»:
- номер и дата исходного документа;
- склад;
- начало/конец/общее время сборки;
- всего/собрано/не найдено/пропущено;
- таблица всех товаров;
- штрихкод;
- количество и тип `УПАК/ШТ`;
- сборщик;
- финальный статус;
- время подтверждения;
- статистика каждого сборщика;
- отдельный блок проблемных позиций;
- поле «Проверил»;
- QR-код/ссылка на заказ.

Нужны две формы: короткая печатная A4 и полный электронный отчёт.

## 13. Gmail (следующая фаза)

Отдельный Gmail получает письма с XLSX. Сервис забирает только новые подходящие вложения, вычисляет hash, импортирует заказ, помечает результат как обработанный/ошибка. Повторное письмо не создаёт дубль.

## 14. Критерии v0.1

На тестовом `sample-order-12293.xlsx`:
- определяется документ №12293 от 10.09.2026;
- определяется склад «Основной склад»;
- импортируется ровно 48 товарных строк;
- первая позиция: `КОФЕ MONARCH 3В1 крепкий 10/24 13гр`, barcode `4607001773207`, packageQuantity `1`, pieceQuantity `24`;
- позиции имеют `groupKey`;
- список сортируется по `groupKey`, затем по названию;
- заказ сохраняется в PostgreSQL;
- повторный импорт не создаёт дубль;
- веб-терминал показывает новый заказ и его 48 позиций.
