# CODEX_TASK_07 — Голосовая сборка и звуковые сигналы

## Цель

Добавить в существующий защищённый веб-режим сборщика hands-free режим: приложение озвучивает текущую позицию, слушает короткие русские голосовые команды через гарнитуру и даёт разные понятные звуковые сигналы.

Это промежуточный этап перед нативным Android-приложением. Backend остаётся источником истины.

## Основной сценарий

1. Сборщик входит под своим логином.
2. Открывает свою очередь.
3. Нажимает «Начать голосовую сборку».
4. Приложение озвучивает текущий товар:
   - для упаковочного: «Плитка Alpen Gold Oreo. Два блока.»;
   - для штучного: сначала отдельный сигнал, затем «Штучный товар. Жвачка Love Is. Семь штук.».
5. После окончания озвучивания приложение начинает слушать команды.
6. Сборщик говорит «Взял».
7. Клиент отправляет изменение статуса на сервер.
8. Только после успешного ответа сервера проигрывается сигнал «Принято».
9. Затем проигрывается короткий сигнал перехода и озвучивается следующая позиция.
10. После последней позиции проигрывается отдельный сигнал завершения и произносится «Ваша часть заказа собрана».

## Голосовые команды

Поддержать только финальные распознанные фразы, без опасного fuzzy-match для подтверждающих действий.

- «Взял» — отметить текущую позицию собранной.
- «Повтори» — повторить полное название и количество.
- «Сколько» — произнести только количество и единицу.
- «Не нашёл» / «Не нашел» — отметить позицию как NOT_FOUND.
- «Пропусти» — отметить SKIPPED и перейти дальше.
- «Отмени» — отменить последнее результативное действие через существующий undo API.
- «Осталось» — сказать количество оставшихся позиций.
- «Пауза» — прекратить распознавание.
- «Продолжить» — возобновить распознавание и повторить текущую позицию.

Не добавлять команду «Дальше» как синоним «Взял».

## Звуковые сигналы

Добавить короткие локальные сигналы без внешних CDN:

1. accepted — приятный короткий восходящий сигнал после успешного ответа сервера.
2. next — мягкий короткий сигнал перед следующей позицией.
3. repeat — нейтральный короткий сигнал перед повтором.
4. piece — отдельный узнаваемый двойной сигнал перед штучным товаром.
5. problem — мягкий понижающийся сигнал для «Не найдено» / «Пропущено».
6. unrecognized — два коротких нейтральных сигнала, если финальная фраза не соответствует командам.
7. error — заметный, но не резкий сигнал при ошибке API или потере связи.
8. completed — короткая приятная мелодия завершения личной очереди.

Сигналы должны иметь отдельную функцию/модуль и кнопку тестирования в интерфейсе.

## Озвучивание

Использовать браузерный SpeechSynthesis с русским голосом, если доступен.

Правила:
- во время TTS распознавание речи должно быть приостановлено, чтобы приложение не распознавало собственный голос;
- после окончания TTS выдержать короткую задержку и снова включить микрофон;
- название произносить без лишних технических полей;
- количество формировать из pickingType и фактического количества для отбора;
- для PIECE обязательно произносить «Штучный товар»;
- для REVIEW голосовую сборку позиции блокировать и показать, что требуется решение администратора.

## Распознавание речи

Использовать Web Speech API (SpeechRecognition / webkitSpeechRecognition), если браузер поддерживает.

Требования:
- язык ru-RU;
- continuous/interim можно использовать, но команды выполнять только по final transcript;
- одновременно должен существовать только один экземпляр распознавания;
- корректно восстанавливаться после onend, пока режим не на паузе;
- не запускать повторно recognition во время speechSynthesis;
- состояние микрофона показывать на экране: «слушаю», «говорю», «пауза», «ошибка»;
- если Web Speech API недоступен, показать понятное сообщение, но все большие экранные кнопки должны продолжать работать.

## Интерфейс сборщика

Сделать мобильный экран, где основная текущая позиция занимает большую часть экрана:

- группа;
- название;
- крупное количество;
- крупный маркер «ШТУЧНЫЙ ТОВАР» для PIECE;
- прогресс «5 из 16» и «осталось 11»;
- статус микрофона;
- распознанная последняя команда мелким текстом;
- переключатель «Голос»;
- переключатель «Звуки»;
- кнопки fallback: ВЗЯЛ, ПОВТОРИТЬ, НЕ НАШЁЛ, ПРОПУСТИТЬ, ОТМЕНИТЬ.

Экран должен быть удобен одной рукой и не требовать точного попадания по маленьким кнопкам.

## Надёжность

Критическое правило: сигнал accepted проигрывать только после подтверждения успешной записи сервером.

При сетевой ошибке:
- не считать позицию собранной локально;
- проиграть error;
- оставить текущую позицию;
- показать «Не удалось сохранить. Повторите команду.»;
- не переходить автоматически дальше.

Не допускать двойного запроса, если «Взял» распозналось несколько раз подряд во время выполнения API-запроса.

## Архитектура

Не оставлять всю новую логику в уже большом main.tsx.

Вынести минимум:
- voice/commandParser.ts
- voice/speechRecognition.ts
- voice/speechSynthesis.ts
- audio/soundPlayer.ts
- picker/voicePickerController.ts или эквивалентные модули/хуки.

Названия можно адаптировать к текущей структуре проекта, но ответственность должна быть разделена.

## Тесты

Добавить unit-тесты для чистого парсера команд:
- «взял» -> TAKE
- «Взял.» -> TAKE
- «не нашел» -> NOT_FOUND
- «не нашёл» -> NOT_FOUND
- «повтори» -> REPEAT
- «сколько» -> QUANTITY
- «пропусти» -> SKIP
- «отмени» -> UNDO
- «осталось» -> REMAINING
- неизвестная фраза -> UNKNOWN
- «дальше» -> UNKNOWN

Добавить тесты формирования фразы позиции:
- PACKAGE;
- PIECE;
- корректные русские единицы в простом виде;
- REVIEW не должен запускать голосовое подтверждение.

Если browser API трудно тестировать в Vitest, обернуть их адаптерами и тестировать бизнес-логику отдельно.

## Definition of Done

Этап считается готовым, когда:

1. Сборщик может включить голосовой режим на странице сборки.
2. Текущая позиция автоматически произносится.
3. Команда «Взял» реально закрывает позицию через существующий защищённый API.
4. После подтверждения слышен accepted-сигнал и открывается следующая позиция.
5. Работают «Повтори», «Сколько», «Не нашёл», «Пропусти», «Отмени», «Осталось», «Пауза».
6. Штучный товар визуально и голосом явно отличается от упаковочного.
7. TTS не вызывает ложные команды микрофона.
8. Ошибка сервера не сопровождается звуком успешного подтверждения.
9. Кнопочный режим полностью сохраняется.
10. npm test, npm run lint и npm run build проходят.

## Пока не делать

- Gmail-импорт;
- интеграцию 1С;
- нативное Android-приложение;
- wake word в фоне;
- работу микрофона при закрытом экране или свернутом браузере.
