# Codex Task 05 - расширенная аналитика

Работай в этом репозитории. Главный источник требований - `SPEC.md`.

Первые четыре этапа завершены: заказ импортируется, распределяется, собирается, проверяется, закрывается, выгружается в PDF, а главный терминал показывает оперативную сводку и журнал импортов.

Цель задачи: дать руководителю смены понятную аналитику по заказам, обработанным позициям и работе сборщиков без изменения складского процесса.

## Сделать

1. Добавить агрегированный API аналитики с периодами 7, 30 и 90 дней.
2. Возвращать число созданных, завершённых и закрытых заказов.
3. Возвращать число обработанных, собранных, не найденных и пропущенных позиций.
4. Рассчитывать долю успешно собранных позиций и среднее время сборки заказа.
5. Формировать дневную динамику созданных/завершённых заказов и результатов по позициям.
6. Формировать показатели сборщиков: обработано, собрано, не найдено, пропущено и процент успеха.
7. Не считать одну позицию дважды при повторном действии в выбранном периоде: использовать её последнее итоговое событие.
8. Добавить в React/Vite раздел `Аналитика` с переключателем периода, KPI, дневной диаграммой и таблицей сборщиков.
9. Корректно показывать пустой период и адаптировать экран для мобильной ширины.
10. Обновить README и тесты.

## API

- `GET /api/analytics?days=7|30|90`

## Автотесты

1. Значение `days` принимает только 7, 30 или 90.
2. Ответ содержит полный непрерывный ряд дней, включая дни без событий.
3. Последнее итоговое событие позиции заменяет более раннее и не увеличивает общее число позиций.
4. Интеграционный складской сценарий отражается в итогах и статистике сборщиков.
5. Ответ не содержит `passwordHash` и другие секреты.

## Не делать пока

- Android-приложение;
- распознавание речи и звуковые сигналы;
- Gmail API;
- интеграцию 1С;
- внешнюю авторизацию.

В конце проверь API на данных тестового заказа, открой экран аналитики в браузере, затем запусти тесты, линтер и сборку.
