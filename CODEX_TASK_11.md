# CODEX_TASK_11 — Android MVP только для сборщика

## Цель
Создать отдельное нативное Android-приложение только для сборщика заказов.
Административный терминал, загрузка XLSX, распределение, аналитика, управление работниками и проблемы остаются только в web.

Android-приложение должно использовать уже существующий backend API на Amvera.

## Технология
- Kotlin
- Jetpack Compose
- minSdk 26 или ниже, если это не усложняет аудио/распознавание
- targetSdk — актуальный стабильный
- архитектура MVVM
- Retrofit/OkHttp для API
- DataStore для несекретных настроек
- EncryptedSharedPreferences или Android Keystore для токена сборщика

## 1. Экран входа
Поля:
- логин
- пароль
- кнопка «Войти»

Использовать существующий POST /api/picker/login.
После входа хранить picker token безопасно на устройстве.
Сессия должна восстанавливаться после перезапуска приложения, пока token валиден.

При 401 очищать токен и возвращать на экран входа.

## 2. Главный экран сборщика
После входа показывать только личную очередь сборщика.

Использовать GET /api/picker/queue.

Показывать крупно:
- название текущего товара
- количество
- тип: БЛОК / ШТУЧНЫЙ
- штрихкод мелко
- прогресс: например 7 / 16
- осталось позиций

Одна текущая позиция на экран.

## 3. Голос
Основной голос — Yandex SpeechKit Alena через существующий backend:
- GET /api/picker/speech/settings
- POST /api/picker/speech

Не хранить Yandex API key в Android.

Fallback: Android TextToSpeech на ru-RU.

Использовать существующую серверную очистку/логику фраз или воспроизводить уже подготовленную фразу так, чтобы сохранялись правила:
- не читать 1/12/12, 1/24, 6х12 и подобные упаковочные схемы;
- не читать иероглифы;
- сохранять 3в1, вес, мл и полезные цифры;
- для штучного товара: «Штучный товар. [название]. семь штук.»
- для упаковки: «[название]. два блока.»

## 4. Голосовые команды
Поддержать точные команды:
- «Взял»
- «Повтори»
- «Сколько»
- «Не нашёл» / «Не нашел»
- «Пропусти»
- «Отмени»
- «Осталось»
- «Пауза»
- «Продолжить»

Команда «Дальше» НЕ должна подтверждать товар.

Для MVP можно использовать Android SpeechRecognizer.
Распознавание включается только после окончания TTS/audio.
Во время речи микрофон должен быть выключен.

## 5. Подтверждение позиции
«Взял» -> PATCH /api/picker/items/:id/status со статусом PICKED.

Критично:
- сначала успешный ответ сервера;
- только потом один короткий accepted-сигнал / вибрация;
- только потом переход к следующей позиции;
- при ошибке сети позиция остаётся текущей.

Для NOT_FOUND и SKIPPED использовать существующий picker API.

## 6. Звуки и вибрация
Не использовать постоянный «птик-птик».

Сценарий обычной позиции:
голос -> «Взял» -> сервер OK -> один короткий accepted -> следующая позиция.

Для PIECE:
accepted предыдущей -> один короткий отличительный piece-сигнал -> «Штучный товар...»

Добавить лёгкую вибрацию:
- PICKED: короткая
- problem/error: другая

В настройках сборщика:
- звук ON/OFF
- вибрация ON/OFF
- скорость речи
- источник речи: Alena / голос телефона

## 7. Гарнитура
Корректно работать с Bluetooth-гарнитурой и проводными наушниками.

Для MVP:
- вывод TTS/audio через активное аудиоустройство;
- распознавание через доступный системный микрофон;
- корректно переживать подключение/отключение гарнитуры.

Не делать управление кнопкой гарнитуры в первой версии, если это тормозит релиз.

## 8. Состояния сети
Показывать понятные состояния:
- «Нет связи»
- «Не удалось сохранить. Повторите команду.»
- «Сервер недоступен»

Не отмечать товар собранным локально, пока backend не подтвердил.

Допускается кэшировать текущую очередь для отображения, но результат PICKED/NOT_FOUND/SKIPPED всегда подтверждает сервер.

## 9. Пауза
При «Пауза»:
- не принимать рабочие команды;
- разрешить только «Продолжить»;
- экран показывает состояние «Пауза».

После «Продолжить»:
- повторить текущую позицию;
- снова включить обычное распознавание.

## 10. Завершение
Когда очередь закончена:
- проиграть completed-сигнал;
- вибрация;
- показать крупно «Ваша часть заказа собрана.»
- кнопка «Обновить» на случай нового назначения.

## 11. Экранные кнопки
Голос — основной способ, но должны быть большие fallback-кнопки:
- ВЗЯЛ
- ПОВТОРИ
- НЕ НАШЁЛ
- ПРОПУСТИТЬ
- ОТМЕНИТЬ

Кнопки должны быть удобны в перчатках.

## 12. Настройки
Минимальные настройки:
- источник голоса: Alena / системный
- скорость речи
- звук ON/OFF
- вибрация ON/OFF
- короткие названия ON/OFF, если это возможно согласовать с backend

Сохранять настройки локально.

## 13. Безопасность
- не хранить ADMIN credentials;
- не иметь административных API в UI;
- picker token хранить безопасно;
- не логировать пароль/token;
- Yandex key только на backend;
- HTTPS обязателен.

## 14. Конфигурация backend URL
Для debug использовать настраиваемый base URL.
Для release использовать production Amvera HTTPS URL через BuildConfig.
Не хардкодить localhost в release.

1. Проект открывается в Android Studio.
2. Debug APK собирается.
3. Вход сборщика работает через production API.
4. Личная очередь загружается.
5. Текущий товар озвучивается.
6. «Взял» подтверждает сервер и переходит дальше.
7. При сетевой ошибке позиция не теряется.
8. Работают основные голосовые команды.
9. Alena работает через backend, без ключа на телефоне.
10. Есть fallback на Android TTS.
11. Нет административной части.
12. npm test / lint / build:prod существующего web/backend продолжают проходить.
13. ./gradlew test проходит.
14. ./gradlew assembleDebug проходит.
