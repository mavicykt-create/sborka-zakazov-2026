# CODEX_TASK_09 — Yandex SpeechKit Alena с безопасным fallback

## Цель

Подготовить серверную интеграцию Yandex SpeechKit для голоса Alena, не добавляя настоящий API-ключ в репозиторий. Системный браузерный TTS остаётся резервным вариантом.

## Безопасность

- Никогда не передавать YANDEX_SPEECHKIT_API_KEY в браузер.
- Ключ читается только backend из environment.
- Не логировать ключ, Authorization headers или секреты.
- В .env.example добавить только пустой placeholder.
- Если ключ отсутствует, приложение должно полностью работать на системном TTS.

Переменные:
YANDEX_SPEECHKIT_API_KEY=
YANDEX_SPEECHKIT_FOLDER_ID=
YANDEX_SPEECHKIT_VOICE=alena

Перед реализацией сверить актуальную официальную документацию Yandex SpeechKit TTS и используемый endpoint/формат запроса. Не угадывать API.

## Backend

Добавить сервис speech/yandexSpeechKitService.ts или эквивалент.

Добавить защищённый endpoint для авторизованного сборщика:
POST /api/picker/speech

Body:
{
  "text": "ПЛИТКА Alpen Gold Oreo. два блока."
}

Требования:
- сервер принимает только текст для озвучки;
- ограничить разумную длину текста;
- очистка названия остаётся на нашей стороне до синтеза;
- backend вызывает Yandex SpeechKit с voice=alena;
- возвращает аудио с корректным Content-Type;
- таймаут внешнего запроса;
- понятная ошибка при недоступности провайдера;
- никакого API-ключа в ответах.

Добавить GET /api/picker/speech/settings, который возвращает только безопасное:
{
  "yandexEnabled": true/false,
  "voice": "alena"
}

## Frontend

В настройках голосовой сборки добавить источник голоса:

- Alena — Yandex SpeechKit
- Голос телефона

Если backend сообщает yandexEnabled=false:
- Alena показать как недоступную;
- автоматически использовать голос телефона.

Если выбран Alena:
1. получить готовую очищенную фразу;
2. запросить аудио через защищённый /api/picker/speech;
3. проиграть аудио;
4. во время проигрывания микрофон не должен слушать;
5. после окончания аудио через ~200 мс снова включить распознавание.

Если запрос SpeechKit завершился ошибкой или timeout:
- не останавливать сборку;
- автоматически произнести ту же фразу системным TTS;
- показать небольшое сообщение "Alena недоступна — используется голос телефона";
- не проигрывать error-сигнал, если fallback успешно произнёс фразу.

## Кэширование

Чтобы не платить и не ждать повторный синтез одной и той же фразы:
- добавить серверный in-memory LRU/TTL cache или файловый cache для синтезированного аудио;
- ключ кэша строить из voice + нормализованный текст + параметров речи;
- повтор команды "Повтори" должен использовать кэш, если аудио уже синтезировано;
- предусмотреть возможность позже заменить кэш на Redis без изменения API.

## Скорость

Нужно сохранить ощущение быстрого складского голоса.
Использовать поддерживаемый SpeechKit способ задания скорости, если он есть в актуальном API.
Целевая скорость Alena должна соответствовать примерно нашему системному 1.22x.
Не применять браузерный playbackRate поверх речи, если SpeechKit позволяет корректно синтезировать нужный темп.

## Существующая логика

Не ломать:
- команды Взял/Повтори/Сколько/Не нашёл/Пропусти/Отмени/Осталось/Пауза/Продолжить;
- одиночные accepted и piece сигналы;
- короткие названия;
- удаление упаковочных схем и CJK;
- правило accepted только после успешного ответа backend;
- fallback-кнопки.

## Тесты

Добавить тесты без реального обращения к Yandex:
- ключ отсутствует -> yandexEnabled=false;
- секрет не попадает в settings;
- успешный mock SpeechKit возвращает аудио;
- provider error -> frontend/controller использует системный fallback;
- повтор одной фразы использует cache;
- слишком длинный/пустой текст отклоняется;
- авторизация picker endpoint обязательна.

Реальный API-ключ в тестах не использовать.
