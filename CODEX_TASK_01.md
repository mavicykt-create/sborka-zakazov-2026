# Codex Task 01 — фундамент и импорт XLSX

Работай в этом репозитории. Главный источник требований — `SPEC.md`.

Цель задачи: довести v0.1 до реально запускаемого состояния.

## Сделать

1. Backend `apps/api` на TypeScript + Fastify.
2. PostgreSQL + Prisma по схеме из `apps/api/prisma/schema.prisma`.
3. `POST /api/orders/import-xlsx` с multipart загрузкой XLSX.
4. Парсер XLSX должен искать заголовки, а не полагаться только на фиксированные номера строк. Для текущего формата учесть merged cells и две колонки количества между `Количество` и `Цена`.
5. Определять `PACKAGE / PIECE / REVIEW` согласно `SPEC.md`.
6. Генерировать `groupKey` из первого слова и сортировать позиции.
7. Защита от повторного импорта.
8. `GET /api/orders`, `GET /api/orders/:id`.
9. React/Vite admin: главная страница + список заказов + карточка заказа с таблицей позиций.
10. На UI явно показывать `УПАК`, `ШТ` или `ПРОВЕРИТЬ`.
11. Автотест парсера на `test-data/sample-order-12293.xlsx`. Ожидается 48 строк и данные первой позиции из `SPEC.md`.
12. Добавить понятные команды запуска в README.

## Не делать пока

- Android;
- распознавание речи;
- Gmail API;
- PDF;
- сложную аналитику;
- интеграцию 1С.

## Требования к качеству

- Не хардкодить номер документа 12293 или 48 позиций в рабочем коде.
- Отдельный модуль XLSX parser, покрытый тестами.
- Валидировать данные и возвращать понятные ошибки импорта.
- Не хранить пароль в открытом виде (когда появятся пользователи).
- Не использовать цены для определения количества, кроме как необязательную sanity-check эвристику.
- Все даты хранить timezone-aware / UTC в БД, исходную дату документа хранить отдельно как календарную дату.

В конце запусти тесты и линтер, исправь ошибки и кратко опиши изменённые файлы.
